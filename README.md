# Shorthack

Проект хакатона. Интеграция с Yandex Cloud API (авторизация по API-ключу сервисного аккаунта).

> Описание задачи и архитектура будут добавлены после получения условия.

## Быстрый старт

```bash
cp .env.example .env   # заполнить YC_API_KEY и YC_FOLDER_ID
```

Секреты в репозиторий не коммитим: `.env` в `.gitignore`, в PR попадает только `.env.example`.

## Работа в команде

**Ветки**

- `main` — защищённая, только через PR. Всегда должна собираться.
- Рабочие ветки: `feat/<area>-<кратко>`, `fix/<area>-<кратко>`, например `feat/api-yc-client`.
- Одна задача = одна ветка = один PR. Ветку берём от свежего `main`.

**Правила, чтобы не ловить конфликты**

- За каждым участником закреплена своя зона (каталог/модуль). В чужую зону — только через договорённость.
- Контракты (схемы запросов/ответов, интерфейсы модулей) фиксируются ДО реализации и меняются отдельным PR с уведомлением команды.
- `git pull --rebase origin main` перед пушем.

**PR**

- Название: `[area] что сделано`.
- В описании: что делает, как проверить, какие переменные окружения нужны.
- Мержим только зелёный PR; ревью — минимум один человек.

**Задачи**

Постановки лежат в `docs/tasks/NN-<роль>-<задача>.md` — самодостаточное ТЗ, которое можно целиком скопировать в чат с LLM и получить рабочий код.
