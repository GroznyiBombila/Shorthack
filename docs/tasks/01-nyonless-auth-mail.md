# Задача 1 — авторизация по коду и отправка почты

**Исполнитель:** nyonless · **Срок:** T+2:30 · **Зависимостей нет** — можно начинать сразу.

Эту постановку можно целиком скопировать в чат с LLM: контекста ниже достаточно.

## Контекст

Делаем сайт ИИ-помощника поддержки МИСИС. Пользователь (студент или абитуриент) задаёт
вопрос, помощник либо отвечает сам, либо предлагает создать заявку. **Заявку можно создать
только после подтверждения почты кодом** — это отсекает спам и даёт поддержке проверенного
автора. Готовая заявка уходит письмом на почту поддержки.

Твоя зона — два независимых модуля: подтверждение почты и отправка писем. **LLM в них не
участвует вообще**, это чистая серверная логика. Остальной код тебя не касается, ты отдаёшь
два модуля с понятными функциями.

## Стек

Python 3.11, стандартная библиотека + `pytest`. База — SQLite (`var/app.db`), через встроенный
`sqlite3`. Никаких Django, SQLAlchemy, Redis и внешних сервисов.

## Файл 1: `app/auth.py`

```python
CORPORATE_DOMAINS = {"misis.ru", "edu.misis.ru"}

class InvalidEmail(Exception): ...
class RateLimited(Exception):      # .retry_after_sec
class InvalidCode(Exception):      # .attempts_left
class CodeExpired(Exception): ...
class TooManyAttempts(Exception): ...

def classify_email(email: str) -> str:
    """'student' для корпоративных доменов, 'applicant' для любых других.
    Нормализует адрес (обрезка пробелов, нижний регистр). InvalidEmail на мусоре."""

def request_code(email: str, ip: str) -> dict:
    """Генерирует код, сохраняет его ХЭШ, отправляет письмо через mailer.send().
    Возвращает {'user_type', 'ttl_sec', 'resend_after_sec'}."""

def verify_code(email: str, code: str) -> dict:
    """Проверяет код. Успех → {'token', 'user_type', 'expires_at'}.
    Иначе поднимает InvalidCode / CodeExpired / TooManyAttempts."""

def validate_token(token: str) -> dict | None:
    """Возвращает {'email', 'user_type', 'expires_at'} или None, если токен
    недействителен, испорчен или просрочен."""
```

### Требования

- Код — **6 цифр**, генерация только через `secrets.randbelow`, не через `random`.
- В базе хранится **не сам код, а его хэш** (`sha256(code + соль)`, соль своя на каждый код).
- Время жизни кода — 600 секунд. Максимум 5 попыток ввода, потом код сгорает.
- Повторная отправка — не чаще раза в 60 секунд.
- Лимиты: не больше 3 кодов на один адрес за 10 минут и 20 запросов с одного IP за час.
- Сравнение кодов — через `hmac.compare_digest`, не через `==`.
- Токен сессии — подписанный `hmac-sha256` по `SECRET_KEY` из окружения, живёт 30 минут.
  Формат: `base64(json_payload).base64(signature)`. Проверка подписи обязательна.
- **Код не должен попадать в логи ни при каких условиях.** В логах — только адрес и результат.
- Успешная проверка кода гасит его: повторно тот же код не проходит.
- Время берётся через параметр или функцию-обёртку, а не через прямой `time.time()` в теле —
  иначе тесты на истечение срока написать нечем.

## Файл 2: `app/mailer.py`

```python
def send(to: str, subject: str, body_text: str, body_html: str | None = None) -> dict:
    """Отправляет письмо. Возвращает {'status', 'message_id', 'error'}.
    status: 'sent' | 'mocked' | 'failed'."""
```

### Требования

- Два режима по переменной `MAIL_MODE`:
  - `mock` (по умолчанию) — письмо не отправляется, а записывается файлом в `var/outbox/`
    с именем `{timestamp}_{to}.eml`, статус `mocked`;
  - `smtp` — реальная отправка через `smtplib.SMTP_SSL`, параметры из окружения
    `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`.
- Тема письма кодируется по правилам MIME — **кириллица в теме обязана приходить читаемой**.
- Таймаут SMTP — 10 секунд. Любая ошибка отправки перехватывается и возвращается как
  `{'status': 'failed', 'error': '...'}`; исключение наружу не летит.
- Никаких паролей в коде — только из окружения.

**Режим `mock` — не заглушка на выброс, а штатный режим демо.** На площадке SMTP может быть
закрыт, и защита не должна от этого зависеть. Делай его аккуратно.

## Тесты: `tests/test_auth.py`, `tests/test_mailer.py`

Минимум, который должен проходить:

1. `classify_email` различает `@misis.ru`, `@edu.misis.ru` и `@gmail.com`, режет пробелы и регистр.
2. Мусорный адрес (`"привет"`, `"a@b"`, пустая строка) → `InvalidEmail`.
3. Верный код проходит, неверный даёт `InvalidCode` с уменьшающимся `attempts_left`.
4. На 6-й попытке — `TooManyAttempts`.
5. Код, которому больше 600 секунд, даёт `CodeExpired`.
6. Использованный код повторно не проходит.
7. Четвёртый запрос кода за 10 минут на один адрес → `RateLimited`.
8. `validate_token` принимает свежий токен и отвергает испорченный, чужой и просроченный.
9. `send` в режиме `mock` создаёт файл в `var/outbox/`, тема с кириллицей читается.

## Критерии приёмки

- `pytest tests/ -q` — зелёный.
- Ни одного обращения к сети в тестах.
- Модули импортируются независимо друг от друга и от остального проекта (`app/auth.py`
  тянет только `app/mailer.py` и стандартную библиотеку).
- В `.env.example` добавлены все новые переменные.

Не трогай другие файлы проекта. Не добавляй зависимостей в `requirements.txt` без согласования.
