# Задача 2 — интерфейс помощника и слайды защиты

**Исполнитель:** antitaxi · **Срок:** экраны T+3:00, слайды T+5:00 · **Зависимостей нет** —
API мокается по контракту, ждать бэкенд не нужно.

---

## Контекст

Сайт ИИ-помощника поддержки МИСИС. Пользователь — **поступающий, студент или преподаватель**,
который пришёл с вопросом про поступление, учёбу или внеучебку. Он выбирает свою роль, пишет
вопрос своими словами и получает ответ выжимкой со ссылкой на раздел misis.ru. Если ответа
нет — помощник предлагает создать обращение: человек либо подтверждает почту кодом и получит
ответ, либо отправляет анонимно и ответа не получит.

Жюри смотрит демо один раз и с проектора. Интерфейс должен читаться с дальнего ряда.

## Стек

Один HTML-файл + CSS + ванильный JS. **Без сборки, без npm, без React.** Файлы кладутся в
`web/`: `index.html`, `style.css`, `app.js`. Бэкенд отдаёт их статикой.

## Экраны

**Главный экран.** Ползунок с тремя положениями — «поступающий / студент / преподаватель» —
и крупная кнопка «Задать вопрос». Больше ничего. Роль определяет, в какой части базы знаний
помощник ищет ответ, поэтому выбор должен быть очевидным и заметным.

**Чат помощника.** Привычный интерфейс языковой модели: лента сообщений, поле ввода внизу,
индикатор набора. Никаких настроек, моделей и параметров. Сверху два раздела-вкладки:

- **Задать вопрос** — основной режим. Помощник отвечает выжимкой и ссылками на разделы
  misis.ru. Если ответа нет — прямо в ленте появляется предложение создать обращение с
  кнопкой.
- **Создать обращение** — путь подачи заявки, доступен и сам по себе.

Одно сообщение может распасться на несколько вопросов: по одному ответ есть, по другому —
нет. Карточки ответов и предложение создать обращение должны нормально выглядеть рядом.

**Развилка доступа.** После нажатия «создать обращение» — выбор из двух вариантов:

- «Подтвердить почту» — придёт ответ от поддержки;
- «Остаться инкогнито» — обращение дойдёт, но **ответить будет некуда**.

Предупреждение про отсутствие обратной связи должно быть видно **до** отправки, а не после.
Человек имеет право выбрать анонимность осознанно, а не обнаружить это потом.

**Подтверждение почты.** Поле адреса, затем экран ввода 6-значного кода. Нужны состояния:
отсчёт до повторной отправки, «осталось N попыток», «код истёк».

**Уточнение.** Помощник задаёт 1–3 вопроса, которых не хватает для обращения. Поля ввода с
подписями, текст подписей приходит из ответа API. Показывается прямо в ленте чата.

**Обращение отправлено.** Номер крупно, тема письма, текст обращения, что будет дальше.
Для анонимного — отдельная формулировка: ответа не будет.

## Контракт API

Полностью описан в [docs/API.md](../API.md) — эндпоинты, поля, коды ошибок. Работай по нему.

Пока бэкенда нет — режим мока: `window.USE_MOCK = true` вверху `app.js`, ответы берутся из
объекта с примерами прямо из `docs/API.md`. Когда бэкенд будет готов, флаг переключается в
`false`, и больше ничего не меняется. **Оба режима должны работать до конца** — на защите мок
может спасти демо.

## Обязательно обработать

- Загрузка: разбор занимает 3–7 секунд, нужен внятный индикатор с текстом вроде
  «Разбираю обращение…» — пустой экран на пять секунд выглядит как зависание.
- Ошибки API: показать сообщение, дать повторить, не терять введённый текст.
- Код 429 на запросе кода — показать, через сколько секунд можно повторить.
- Мобильная ширина 375px — вёрстка не должна разъезжаться.

## Стиль

Фирменные цвета МИСИС, светлая тема, крупный шрифт (базовый от 16px), высокий контраст.
Никаких мелких серых подписей на сером фоне. Анимаций минимум — они съедают время и на
проекторе выглядят хуже, чем кажется.

## Слайды защиты (5–7 слайдов, к T+5:00)

Строго по трём вопросам жюри из технического задания:

1. Титул: название, состав команды.
2. Проблема: поступающий и студент ищут ответ вручную по большому сайту, а поддержка
   получает обращения без половины нужных данных.
3. Решение: схема потока «вопрос → разбор → ответ или заявка».
4. **Где LLM, а где обычный код** — таблица, содержимое пришлю я. Это ключевой слайд,
   на нём построена половина оценки.
5. Демо: два-три скриншота ключевых экранов.
6. Ограничения и что добавили бы дальше.

## Критерии приёмки

- Все экраны открываются и переключаются в режиме мока без бэкенда, включая оба
  варианта развилки доступа.
- Ни одной незакрытой ошибки в консоли браузера.
- Страница читается с расстояния трёх метров.

## Чего НЕ делать

Не подключай библиотеки с CDN — на площадке может не быть интернета. Не придумывай свои поля
API: если чего-то не хватает, напиши мне, и мы поправим контракт централизованно.
