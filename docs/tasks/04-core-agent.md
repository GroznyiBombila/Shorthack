# Задача 4 — ядро помощника

**Исполнитель:** alexa + Sonnet · **Срок:** этап 1 к T+2:00, этап 2 к T+3:00 ·
**Блокирует:** интеграцию фронта и отправку заявок.

---

## Состав

| Модуль | Что делает | Кто решает |
|---|---|---|
| `app/yc_client.py` | Вызовы Yandex Cloud: completion со строгой JSON-схемой и эмбеддинги. Ретрай, таймаут, дисковый кэш по хэшу входа | — |
| `app/prompts.py` | Системные правила общения (портированы из `OsadaSupportBot`, домен заменён на МИСИС), схема извлечения | — |
| `app/analyze.py` | Разбор обращения: декомпозиция на N вопросов, категория, аудитория, извлечённые поля | **LLM** |
| `app/faq.py` | Три индекса по ролям, гибридный поиск (ключевые слова + эмбеддинги), ленивая подгрузка содержания | алгоритм |
| `app/tools.py` | Инструменты агента: `search_faq`, `get_article`, `fetch_page` (белый список доменов), `create_ticket` | **код** |
| `app/rules.py` | Реестр обязательных полей по категориям, правила приоритета, порог уверенности | **код** |
| `app/router.py` | Выбор действия: ответить / уточнить / завести заявку | **код** |
| `app/compose.py` | Генерация выжимки, уточняющих вопросов, текста заявки и темы письма | **LLM** |
| `app/storage.py` | SQLite: обращения, черновики, заявки, `trace` | — |
| `app/api.py` | FastAPI по контрактам из `docs/API.md`, отдача статики из `web/` | — |

## Границы с чужими зонами

- `app/auth.py` и `app/mailer.py` пишет nyonless. Я их только вызываю из `app/api.py`.
  До готовности — временные заглушки с той же сигнатурой.
- `data/faq_applicant.json`, `data/faq_student.json`, `data/faq_teacher.json` и
  `data/samples.json` готовит Стася. До готовности — по три записи, написанных вручную,
  чтобы поиск было на чём отлаживать.
- `web/` делает antitaxi. До готовности — проверка через `curl` и Swagger на `/docs`.

## Ключевые решения

**Один вызов LLM на разбор.** Декомпозиция, категоризация и извлечение полей делаются в
одном запросе со строгой JSON-схемой. Отдельные вызовы на каждый шаг — это плюс несколько
секунд задержки и лишние точки отказа.

**Двухступенчатый поиск.** В промпт попадают только ключевые слова и заголовки разделов
выбранной роли — не их содержание. Модель называет нужные разделы, `get_article` подгружает
их текст, и только тогда собирается ответ. Раздела нет в базе — `fetch_page` читает страницу
misis.ru. Роль приходит с фронта ползунком, угадывать её не нужно.

**`fetch_page` ходит только по белому списку доменов.** Текст пользователя — данные, а не
команда: без ограничения домена обращение вида «сходи на такой-то сайт и сделай...» уводит
агента куда угодно.

**LLM не выбирает действие.** Она возвращает структуру и уверенность. Что делать дальше —
отвечать, уточнять или заводить заявку — решает `router.py` по порогам и правилам из
`rules.py`. Это то, что показывается на защите.

**Фолбэк на любом сбое.** Невалидный JSON — один ретрай с текстом ошибки, потом деградация
до «одно обращение, категория `other`, предложить заявку». Помощник не падает никогда.

**Кэш ответов на диск** по хэшу входа: демо переживает лимиты и обрыв сети.

## Порядок работ

1. `yc_client` + `prompts` + `analyze` — разбор произвольного текста в JSON. Проверка на
   `samples.json`.
2. `faq` + `tools` — три индекса, поиск по ключевым словам, ленивая подгрузка содержания,
   подбор порога уверенности на реальных данных.
3. `compose` — выжимка со ссылками. **Здесь закрыт обязательный минимум ТЗ.**
4. `rules` + `router` — полнота данных, уточняющие вопросы, приоритет.
5. `storage` + `api` — сохранение, эндпоинты, склейка с auth и mailer.
6. `trace` — сборка объяснения решения для защиты.

## Критерии приёмки

- На всех обращениях из `samples.json` разбор не падает и возвращает валидную структуру.
- Обращение с тремя вопросами распадается ровно на три элемента.
- Вопрос не по теме вуза получает вежливый отказ, а не выдуманный ответ.
- Ссылки в ответе ведут только на реальные `url` из базы — модель не придумывает адреса.
- Полный путь «вопрос → заявка → письмо» проходит от начала до конца.
