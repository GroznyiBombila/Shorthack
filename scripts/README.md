# scripts

Служебные скрипты. Запускать из корня проекта.

## warm_cache.py — прогрев кэша модели

Лимиты Groq общие на всю команду: **1000 запросов в сутки и 8000 токенов в минуту**.
На защите проект не должен ходить в сеть: все демонстрационные обращения обязаны
отдаваться из дискового кэша (`var/cache`, в контейнере `/data/cache`).

```bash
python scripts/warm_cache.py --dry-run   # что уже в кэше, без единого запроса к модели
python scripts/warm_cache.py             # прогреть всё, что холодное
```

Сценарии лежат в [`data/demo/scenarios.json`](../data/demo/scenarios.json).

**Когда прогревать:**

- перед защитой — обязательно, и обязательно на той машине, где будет демо
  (кэш дисковый: прогрев на ноутбуке не поможет контейнеру на сервере);
- после любой правки промптов в `app/prompts.py` — ключ кэша считается от текста
  промпта, поэтому изменённая запятая обесценивает весь прогрев целиком;
- после смены модели в `.env` — ключ включает и название модели;
- после пополнения базы знаний — ответы собираются из статей, старый кэш отдаст
  ответ по старым статьям.

**Как понять, что прогрев удался:** `--dry-run` печатает «В кэше 10 из 10».
Если хоть один сценарий холодный — на защите он пойдёт в сеть и может словить 429.
