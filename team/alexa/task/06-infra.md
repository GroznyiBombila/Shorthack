# Задача 6 — контейнер и хранилище данных

**Исполнитель:** alexa + Sonnet · **Срок:** контейнер к T+3:30, деплой на VPS к T+4:30.

---

## Что делаем

Приложение и все его данные упаковываются в один контейнер с примонтированным томом. Внутри
тома живёт всё, что помощник читает и пишет: база знаний, расписания, SQLite с профилями и
обращениями, кэш ответов модели, исходящие письма.

```
/data
  ├── faq/            faq_applicant.json, faq_student.json, faq_teacher.json
  ├── schedule/       *.xls по институтам + разобранный кэш
  ├── app.db          SQLite: профили, коды подтверждения, обращения, trace
  ├── cache/          ответы модели по хэшу запроса
  └── outbox/         письма в mock-режиме
```

Приложение не должно знать, где физически лежит том: путь приходит из `DATA_DIR`,
по умолчанию `./var`. Так одинаково работает и локальный запуск, и контейнер.

## Состав

- `Dockerfile` — python:3.11-slim, установка зависимостей, запуск uvicorn.
- `docker-compose.yml` — сервис приложения, том `/data`, переменные из `.env`, порт наружу.
- `Makefile` или `run.sh` — одна команда на подъём, одна на прогон тестов.
- `README`: раздел «Запуск» на пять строк. Кейс прямо требует краткую инструкцию запуска,
  и жюри её читает.

## Порядок и приоритеты

1. **Локальный запуск без контейнера** — `uvicorn app.api:app --reload`. Это то, на чём
   реально идёт разработка все шесть часов.
2. **Контейнер** — собирается и поднимается одной командой.
3. **Деплой на свой VPS** — публичный адрес, который показываем на защите.

### Деплой

VPS и доступы у нас есть, поэтому решение живёт по публичному адресу, а не только на ноутбуке.
Порядок:

- образ собирается локально, на сервер уезжает через `docker compose` по SSH;
- `.env` лежит **только на сервере**, в образе ключей нет;
- том с данными на сервере — постоянный, переживает передеплой;
- деплой делается одной командой и повторяется столько раз, сколько нужно.

**Страховка на защиту обязательна.** Публичный адрес выглядит сильнее локального прототипа,
но добавляет внешнюю зависимость: упавший сервер или сеть в зале — это провал демо. Поэтому
локальный запуск остаётся рабочим до конца, и на защиту идём с обоими вариантами: показываем
развёрнутое, но можем за пятнадцать секунд переключиться на localhost.

**Заморозка.** После code freeze на сервер уезжает ровно то, что репетировали, и больше
ничего не передеплоивается.

## Требования

- Секреты только через переменные окружения, ни одного ключа в образе.
- Контейнер поднимается на чистой машине без ручных шагов, кроме заполнения `.env`.
- Том переживает пересборку образа: данные не теряются.
- Приложение стартует и без базы знаний — с пустым FAQ отвечает «ответа нет, создать
  обращение?», а не падает.

## Критерии приёмки

- `docker compose up` на чистой машине даёт работающее приложение.
- Приложение открывается по публичному адресу VPS.
- Передеплой не теряет данные из тома.
- Инструкция запуска в README проверена с нуля — по ней проходит человек, не писавший код.
