# Задача 2 — интерфейс помощника и слайды защиты

**Исполнитель:** antitaxi · **Срок:** каркас и главный экран T+1:30, все экраны T+3:00,
слайды T+5:00 · **Зависимостей нет** — API мокается по контракту, ждать бэкенд не нужно.

Постановку можно целиком скопировать в чат с моделью.

---

## Контекст

Сайт ИИ-помощника поддержки МИСИС. Пользователь — **поступающий, студент или преподаватель**,
который пришёл с вопросом про поступление, учёбу или внеучебную жизнь. Он выбирает свою роль,
пишет вопрос своими словами и получает ответ выжимкой со ссылкой на раздел misis.ru. Если
ответа нет — помощник предлагает создать обращение: человек либо подтверждает почту кодом и
получит ответ, либо отправляет анонимно и ответа не получит.

**Кто это увидит:** жюри, один раз, с проектора, из дальнего ряда. Интерфейс должен читаться
с трёх метров и не требовать пояснений. Красивая мелочь, которую не видно с проектора, не
стоит ни минуты твоего времени; крупный понятный экран стоит всего.

## Стек и файлы

Один HTML + CSS + ванильный JS. **Без сборки, без npm, без React, без CDN.**

```
web/
  index.html    вся разметка всех экранов сразу, переключаются классом
  style.css     переменные + компоненты
  app.js        состояние, запросы, мок
```

Почему без сборки: на площадке может не быть интернета, а `npm install` в чужой сети — это
потерянные двадцать минут и риск не открыть страницу на защите.

Все экраны лежат в разметке сразу и переключаются через `hidden` или класс `is-active`.
Никаких шаблонизаторов и генерации разметки строками — кроме списков (сообщения, карточки пар),
их собирай через `<template>` и `cloneNode`.

## Дизайн-система

Сначала опиши токены, потом верстай. Это десять минут, которые экономят час правок.

### Цвета

Фирменные цвета возьми с misis.ru — открой сайт и пипеткой сними основной синий и акцент.
Если не найдёшь за пять минут, бери запасную палитру и не думай об этом больше:

```css
:root{
  --bg:#ffffff;          /* фон страницы */
  --surface:#f5f7fb;     /* карточки, поля ввода */
  --line:#dde3ee;        /* границы */
  --text:#101828;        /* основной текст */
  --text-dim:#5a6474;    /* подписи — минимальный контраст 4.5:1, не светлее */
  --brand:#0b2c68;       /* фирменный синий: шапка, основные кнопки */
  --brand-hover:#143a82;
  --accent:#e4002b;      /* акцент: важное, ошибки, приоритет */
  --ok:#1a7f4b;
  --warn:#b26a00;
  --radius:12px;
  --gap:16px;
}
```

Тёмную тему не делаем — на проекторе она хуже читается и это лишний час.

### Типографика

Системный шрифт, никаких подключаемых: `-apple-system, "Segoe UI", Roboto, Arial, sans-serif`.

| Роль | Размер | Начертание |
|---|---|---|
| Заголовок экрана | 28px | 700 |
| Подзаголовок | 20px | 600 |
| Основной текст, сообщения | 17px | 400 |
| Подписи и мета | 15px | 400, `--text-dim` |
| Кнопка | 17px | 600 |

Базовый размер **не меньше 16px**. Межстрочный интервал 1.5 в тексте ответов — их читают.

### Компоненты

- **Кнопка основная**: фон `--brand`, белый текст, высота 48px, радиус `--radius`.
- **Кнопка вторичная**: прозрачная, граница `--line`, текст `--brand`.
- **Кнопка опасная/честная** (инкогнито): граница `--warn`, текст `--warn`.
- **Поле ввода**: высота 48px, граница `--line`, при фокусе — граница `--brand` и видимая
  обводка. Обводку фокуса **не убирай** — по ней ходят с клавиатуры.
- **Карточка**: фон `--surface`, радиус `--radius`, отступ 16px.
- **Пилюля-метка** (категория, приоритет): маленькая, скруглённая, контрастная.

Анимаций минимум: только появление сообщения (fade 120ms) и индикатор набора. Всё остальное
на проекторе выглядит хуже, чем кажется в браузере.

## Экраны

Девять состояний. Ниже — что на каждом, сверху вниз, и что происходит по нажатиям.

### 1. Главный

Единственный экран без чата. На нём ровно три вещи:

1. Заголовок **«Помощник поддержки МИСИС»** и строка под ним: «Отвечу на вопрос про
   поступление, учёбу и студенческую жизнь. Если ответа не найдётся — помогу составить
   обращение».
2. **Ползунок роли** — три положения: «Поступающий · Студент · Преподаватель». Не выпадающий
   список: выбор должен быть виден целиком, без нажатия. Выбранное положение — заливка
   `--brand`, белый текст. По умолчанию «Студент».
3. Кнопка **«Задать вопрос»**, широкая, во всю колонку.

Роль сохраняется в `localStorage` и подставляется при следующем открытии.

**Почему роль решает всё:** от неё зависит, в какой из трёх баз знаний искать ответ. Она
уходит в каждый запрос `POST /api/ask` полем `role` и постоянно видна в шапке.

### 2. Чат

Привычный интерфейс языковой модели. Никаких настроек, выбора моделей и параметров.

```
┌──────────────────────────────────────────┐
│ [ Задать вопрос ] [ Создать обращение ]  │  вкладки
├──────────────────────────────────────────┤
│ ┌────────────────────────────────────┐   │
│ │ сообщение помощника                │   │  лента, скролл вниз
│ └────────────────────────────────────┘   │
│        ┌────────────────────────────┐    │
│        │ сообщение пользователя     │    │  справа, фон --brand
│        └────────────────────────────┘    │
├──────────────────────────────────────────┤
│ [Расписание сегодня][завтра][Выбрать]    │  только у авторизованных
│ ┌──────────────────────────────┐  [→]    │
│ │ Ваш вопрос…                  │         │  textarea, растёт до 5 строк
│ └──────────────────────────────┘         │
└──────────────────────────────────────────┘
```

Поведение ленты:

- Enter отправляет, Shift+Enter — перенос строки. Подпиши это серым под полем один раз.
- После отправки поле очищается, но **отправленный текст остаётся в памяти**: если запрос
  упал, вернуть его в поле кнопкой «Повторить».
- Лента всегда прокручивается к последнему сообщению.
- Пустое сообщение не отправляется, кнопка отправки недоступна.

**Первое сообщение помощника** зависит от роли, напиши три варианта заранее:
поступающему — «Спросите про поступление: сроки, документы, баллы, общежитие»;
студенту — «Расписание, сессия, стипендия, справки, общежитие»;
преподавателю — «Доступы к системам, расписание аудиторий, оформление документов».

### 3. Ответ помощника — самая важная карточка

Одно сообщение человека может распасться на несколько вопросов: на один ответ есть, на
другой нет. Поэтому ответ — не абзац текста, а **список карточек по числу вопросов**
из `questions[]`.

Карточка с ответом (`answer != null`):

```
┌────────────────────────────────────────┐
│ Сроки подачи документов                │  вопрос, как его понял помощник
│ ─────────────────────────────────────  │
│ Выжимка на два-три предложения.        │  answer.summary
│                                        │
│ Источники:                             │
│ → Приёмная кампания 2026  ↗            │  answer.sources[], новая вкладка
└────────────────────────────────────────┘
```

Карточка без ответа (`answer == null`, `suggest_ticket: true`):

```
┌────────────────────────────────────────┐
│ Нужен ли оригинал аттестата            │
│ ─────────────────────────────────────  │
│ Точного ответа в базе не нашёл.        │
│ [ Создать обращение ]                  │
└────────────────────────────────────────┘
```

Требования:

- Обе карточки должны **нормально выглядеть рядом, в одном ответе**. Это типовой случай,
  а не исключение — проверь его первым.
- Ссылки на misis.ru — всегда `target="_blank" rel="noopener"`.
- Формулировка «не нашёл» — честная. Не пиши «к сожалению, я не смог обработать ваш запрос»:
  помощник не сломался, просто ответа нет в базе.
- Источник обязателен и заметен: жюри должно видеть, что ответ взят из раздела сайта,
  а не выдуман.

### 4. Развилка доступа

Открывается по «Создать обращение». Два варианта, оба крупные, рядом:

```
┌─────────────────────────┐  ┌─────────────────────────┐
│ Подтвердить почту       │  │ Отправить анонимно      │
│                         │  │                         │
│ Придёт ответ от         │  │ Обращение дойдёт, но    │
│ поддержки на указанный  │  │ ответить будет некуда:  │
│ адрес.                  │  │ обратной связи не будет.│
│ [ Подтвердить ]         │  │ [ Отправить анонимно ]  │
└─────────────────────────┘  └─────────────────────────┘
```

**Предупреждение про отсутствие обратной связи показывается ДО отправки, а не после.**
Человек имеет право выбрать анонимность осознанно, а не обнаружить это постфактум. Это
требование, а не пожелание: обманутое ожидание ответа — худшее, что может сделать поддержка.

Анонимный вариант не должен выглядеть как ошибка или что-то стыдное — ровный нейтральный
блок и честный текст.

### 5. Подтверждение почты

Два шага на одном экране.

**Шаг 1 — адрес.** Поле `type="email"`, подпись: «Студентам и преподавателям — корпоративная
почта, поступающим — любая». Кнопка «Получить код».

**Шаг 2 — код.** Шесть цифр, поле с `inputmode="numeric"`, крупное, по центру.

> **Изменение от 12.09: код показывается прямо на экране.** Администратор домена
> `edu.misis.ru` запретил пароли приложений, письмо с кодом физически некуда отправить.
> На сервере поднят флаг `AUTH_SHOW_CODE`, и `POST /api/auth/request-code` возвращает
> лишнее поле `demo_code`. Если оно пришло — показать его отдельной плашкой над полем
> ввода: «Демо-режим: код <b>481920</b>. В рабочем контуре он придёт письмом».
> Плашка обязана выглядеть как временный демо-костыль, а не как часть продукта:
> пунктирная рамка, приглушённый фон. Если `demo_code` в ответе нет — плашки нет,
> экран работает по-старому.

Под полем ввода — четыре состояния, все обязаны быть в моке и показываться на демо:

- отсчёт: «Отправить код повторно через 0:47», кнопка неактивна (`resend_after_sec`);
- неверный код: «Неверный код, осталось попыток: 3» (`attempts_left`);
- истёк: «Код истёк, запросите новый» и активная кнопка повторной отправки;
- `429`: «Слишком часто. Повторите через N секунд» (`retry_after_sec`).

Продуманные состояния ошибок — видимая работа, жюри такое замечает.

### 6. Профиль

Показывается сразу после подтверждения почты, если `filled: false`.

Заголовок: «Расскажите о себе — спрошу один раз». Поля **приходят с сервера**
(`GET /api/profile/fields?role=...`), в вёрстку их не зашиваем:

- студенту: институт (список), учебная группа (список), подгруппа (необязательно);
- преподавателю: кафедра, фамилия и инициалы;
- поступающему форма **не показывается вообще** — профиля у него нет.

Рисуй форму циклом по массиву `fields`: `type` = `text` или `select`, `required` помечает
звёздочкой, `options` наполняет список. Появится новое поле — вёрстку менять не придётся.

Кнопка «Сохранить и продолжить». Под ней ссылка «Пропустить» — но тогда кнопки расписания
не появятся, и это надо честно написать одной строкой рядом.

### 7. Быстрые действия: расписание

Ряд кнопок над полем ввода, **только у авторизованного студента или преподавателя с
заполненным профилем**. У остальных ряда нет вообще: неактивные кнопки не показываем.

- «Расписание на сегодня»
- «Расписание на завтра»
- «Выбрать день» — открывает `<input type="date">`, ответ за выбранную дату.

Ответ приходит в ленту карточками пар:

```
┌────────────────────────────────────────┐
│ Понедельник, 14 сентября · верхняя нед.│
├────────────────────────────────────────┤
│ 2  10:50–12:25                         │
│    Введение в специальность  [лаб]     │
│    Неворошкин В. А. · Л-812-УВЦ        │
├────────────────────────────────────────┤
│ 3  12:40–14:15                         │
│    Математика  [практика]              │
│    Ким-Тян Л. Р. · Л-629               │
└────────────────────────────────────────┘
```

- `kind` переводим: `lecture` — лекция, `practice` — практика, `lab` — лаборатор.,
  `other` — занятие. Показываем меткой-пилюлей, цвета разные.
- `week`: `upper` — «верхняя неделя», `lower` — «нижняя неделя».
- Преподавателя может не быть (физкультура, иностранный язык) — просто не выводим строку.
  Это норма, а не «—» и не ошибка.
- **Пустой список — честное «В этот день занятий нет»**, а не пустая карточка.
- `409 profile_incomplete` — «Чтобы показать расписание, нужна ваша группа» и кнопка,
  открывающая форму профиля.

### 8. Уточнение и предпросмотр

Помощник задаёт 1–3 вопроса, которых не хватает для обращения (`missing_fields[]`).
Показывается **прямо в ленте**, не модальным окном:

```
┌────────────────────────────────────────┐
│ Чтобы оформить обращение, уточните:    │
│                                        │
│ На какое направление подаёте документы?│
│ [__________________________]           │
│                                        │
│ [ Продолжить ]                         │
└────────────────────────────────────────┘
```

Подписи полей приходят из ответа API — свои не придумывай. По «Продолжить» повторно
вызывается `POST /api/ticket/draft` с заполненным `answers`.

**Предпросмотр перед отправкой обязателен.** Когда `ready: true` — показываем тему письма и
текст обращения целиком, кнопки «Отправить» и «Исправить». Человек должен видеть, что уходит
от его имени.

### 9. Обращение принято

> **Изменение от 12.09: письма отменены целиком.** Отправлять почту от корпоративного
> ящика нам не дали, поэтому обращение никуда не уходит — оно встаёт во внутреннюю
> очередь. Сотрудник поддержки отвечает в своей консоли (её делаю не ты, `/operator/`),
> а ответ человек читает здесь же, в интерфейсе. Слова «письмо», «отправлено на почту»,
> «ответ придёт на адрес» с экранов убрать везде.

`POST /api/ticket/submit` теперь отвечает `{ticket_id, subject, delivery: "inbox", anonymous}`.
Поля `sent_to` и `mail_status` больше нет — не рисуй их.

- Номер обращения (`ticket_id`) крупно — его должно быть видно с проектора.
- Кому адресовано (`recipient` из карточки обращения) и тема.
- Что дальше: «Ответ появится здесь, в разделе „Мои обращения“. Мы сохранили номер».
- Для анонимного: «Обращение анонимное. Ответ придёт по этому номеру — сохраните его,
  без номера обращение не найти». Ровно, без упрёка: номер и есть единственный ключ.
- Кнопки: «Мои обращения» (экран 10) и «Задать ещё вопрос» (возврат в чат).

### 10. Мои обращения и переписка — новый экран, обязателен

Раньше эту роль играла почта. Теперь это единственное место, где человек видит ответ,
поэтому экран не второстепенный: на защите именно он доказывает, что петля замкнута.

**Список.** `GET /api/my/tickets` с заголовком `Authorization: Bearer <token>` — только
для подтверждённой почты. Карточка строки: номер, тема, адресат, дата, статус. Статусы
приходят из API, свои не придумывай:

| status | подпись на экране | цвет |
|---|---|---|
| `new` | Принято | серый |
| `in_progress` | В работе | синий |
| `answered` | Есть ответ | зелёный, самый заметный |
| `closed` | Закрыто | приглушённый |

Непрочитанных отметок нет и не выдумывай — их нечем считать.

**Анонимное обращение в списке не появится** (оно ни к кому не привязано). Для него —
поле «Найти по номеру обращения» над списком: ввод `MISIS-2026-0007` →
`GET /api/ticket/{ticket_id}` без токена → тот же экран переписки. Это и есть обещанная
анонимность: номер работает как ключ, и потерявшему номер помочь нечем — так и напиши
в подсказке под полем.

**Переписка.** `GET /api/ticket/{ticket_id}` отдаёт `body` (текст обращения) и `messages` —
список `{author, text, created_at}`, где `author` — `user` или `operator`. Рисуй лентой
сверху вниз: обращение первым блоком, дальше сообщения. Реплики сотрудника и человека
визуально различимы (сторона или фон — на твой вкус, но различимы с проектора).

Внизу — поле «Уточнить» и кнопка: `POST /api/ticket/{ticket_id}/message` с `{text}`.
Ответ ручки — обновлённая карточка целиком, просто перерисуй ленту по нему.

Автообновления нет: кнопка «Обновить» рядом с заголовком. Опрос раз в 20 секунд можно,
но только на открытой карточке и молча.

## Состояния, без которых демо разваливается

Каждое состояние ниже должно быть воспроизводимо в моке одной строчкой — чтобы ты мог
показать его жюри, а не рассказывать словами.

| Состояние | Что показываем |
|---|---|
| Ожидание ответа | Индикатор с текстом «Разбираю обращение…». Разбор занимает 3–7 секунд, пустой экран на это время читается как зависание |
| Сеть недоступна | «Не удалось связаться с помощником» + кнопка «Повторить», введённый текст не потерян |
| Ошибка 500 | То же сообщение, но с номером запроса, если он пришёл |
| 429 на коде | Сколько секунд ждать, кнопка неактивна с обратным отсчётом |
| Неверный код | Сколько попыток осталось |
| Код истёк | Предложение запросить новый |
| Пустое расписание | «В этот день занятий нет» |
| Профиль не заполнен | Приглашение заполнить + кнопка |
| База знаний пуста | Помощник отвечает «ответа нет» и предлагает обращение — не падает |

Правило на все ошибки: **никогда не терять введённый пользователем текст.** Человек написал
абзац, нажал отправить, поймал ошибку — текст обязан вернуться в поле.

## Режим мока

Вверху `app.js`:

```js
window.USE_MOCK = true;   // false — работать с настоящим API
```

Все запросы идут через одну функцию:

```js
async function api(path, options) {
  if (window.USE_MOCK) return mock(path, options);
  const res = await fetch(path, options);
  ...
}
```

Ответы для мока бери **дословно из `docs/API.md`** — они там полные, придумывать не нужно.
Добавь в мок задержку 600–1200 мс, иначе не увидишь собственный индикатор загрузки.

Сделай переключатели сценариев прямо в моке, например:

```js
window.MOCK_CASE = 'two_questions';
// two_questions | all_answered | nothing_found | wrong_code | expired_code
// rate_limited | empty_schedule | server_error
```

Это и есть твой инструмент отладки и твоя страховка на защите: если бэкенд ляжет,
демо проходит целиком на моке, и никто не заметит.

**Оба режима должны работать до самого конца.** Не выпиливай мок, когда подключится API.

## Мобильная ширина и доступность

- Проверь 375px: вёрстка не разъезжается, кнопки не налезают, поле ввода не выпрыгивает.
- Кликабельная область кнопки — минимум 44×44px.
- Ползунок роли на узком экране может стать вертикальным — это нормально.
- Видимая обводка фокуса у всех интерактивных элементов, `:focus-visible`. Её не убираем.
- Весь диалог проходится с клавиатуры: Tab по элементам, Enter отправляет.
- У иконок и кнопок без текста — `aria-label`.
- Контраст текста к фону минимум 4.5:1. Серое по серому на проекторе не читается.

## Слайды защиты (5–7 штук, к T+5:00)

Строго по трём вопросам жюри из технического задания.

1. **Титул**: название решения, состав команды.
2. **Проблема**: поступающий и студент ищут ответ вручную по большому сайту, а поддержка
   получает обращения без половины нужных данных и переспрашивает по три раза.
3. **Решение**: схема потока «вопрос → разбор → ответ из базы знаний или заявка».
4. **Где языковая модель, а где обычный код** — таблица, содержимое пришлю я. Это ключевой
   слайд: на нём построена половина оценки. Главный тезис — модель не принимает решений,
   она только раскладывает текст по полям, а решает детерминированный код.
5. **Демо**: два-три скриншота ключевых экранов.
6. **Ограничения и что дальше**: что не успели и что добавили бы — честно. Жюри ценит
   понимание границ решения выше, чем вид всемогущества.

Шрифт на слайдах крупный, текста мало. Слайд, который надо читать, — потерянный слайд.

## Критерии приёмки

- Все девять экранов открываются и переключаются в режиме мока без бэкенда.
- Смешанный ответ (часть вопросов с ответом, часть без) выглядит правильно.
- Оба варианта развилки доступа проходятся до конца.
- Все четыре состояния кода подтверждения показываются.
- Пустое расписание даёт честный текст, а не пустоту.
- Ни одной незакрытой ошибки в консоли браузера.
- 375px не разъезжается.
- Страница читается с расстояния трёх метров.

## Чего НЕ делать

Не подключай библиотеки, шрифты и иконки с CDN — на площадке может не быть интернета,
и страница просто не откроется. Не придумывай своих полей API: если чего-то не хватает,
напиши мне, поправим контракт централизованно и сразу для всех. Не делай тёмную тему,
анимации переходов между экранами и «красивую» мелкую типографику — это то, что не увидят
с проектора, но на что уйдёт час.
