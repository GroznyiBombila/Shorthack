# nyonless — серверные модули

Ты делаешь две самостоятельные части, которые не зависят от чужого кода.
Обе подключаю к API я, тебе HTTP писать не нужно.

## Что прочитать перед началом

- свою постановку — целиком;
- [формат файла расписания](task/format-raspisaniya.md) — перед задачей 5 обязательно.
  Там разобрана раскладка колонок, деление на верхнюю и нижнюю неделю и ловушка с
  латинской буквой в номере аудитории. Это экономит час реверс-инжиниринга;
- [контракты API](../../docs/API.md) — только чтобы понимать, как твои функции будут вызваны.

## Куда класть

| Что | Куда |
|---|---|
| Код | `app/auth.py`, `app/mailer.py`, `app/profile.py`, `app/schedule_parser.py`, `app/schedule.py` |
| Тесты | `tests/test_auth.py`, `tests/test_schedule.py` |
| Исходные файлы расписаний | `data/schedule/` — пример `itkn-110926.xls` уже там |
| Всё остальное: заметки, черновики, скриншоты | [materials/](materials/) |

## Правила

- Ветка `feat/auth-...` или `feat/schedule-...`, один PR на задачу.
- Чужие файлы не трогаем: если нужно поменять контракт — пишем в чат, меняем отдельным PR.
- Новые зависимости — только те, что названы в постановке, и сразу в `requirements.txt`.
- Пушим по мере готовности, а не одним куском в конце.
