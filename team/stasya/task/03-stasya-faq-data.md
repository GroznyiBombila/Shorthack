# Задача 3 — база знаний по misis.ru и тестовые обращения

**Исполнитель:** Стася · **Срок:** волнами, первая к T+1:00 · **Зависимостей нет**,
код писать не нужно. Работа устроена так, что её можно остановить на любой волне.

---

## Контекст

Делаем ИИ-помощника поддержки МИСИС. На главном экране человек выбирает, кто он —
**поступающий, студент или преподаватель**, — и задаёт вопрос своими словами. Помощник ищет
ответ в базе знаний своей аудитории, отдаёт короткую выжимку со ссылкой на раздел сайта.
Если ответа нет — предлагает создать обращение.

**Без твоих данных помощнику нечего искать.** Это не вспомогательная задача: качество базы
напрямую определяет, будет ли работать демо.

## Как устроен поиск (важно для формата)

Помощник работает в два шага. Сначала он видит **только заголовки и ключевые слова** всех
разделов — по ним выбирает, что открыть. И лишь потом читает содержание выбранного раздела.

Поэтому две части записи делают разную работу:

- `keywords` и `title` отвечают за то, **найдётся ли раздел вообще**;
- `full_text` отвечает за то, **каким будет ответ**, когда раздел уже найден.

Слабые ключевые слова — раздел не найдётся, каким бы хорошим ни было содержание.
Это самое важное поле во всей задаче.

## Часть 1: база знаний — три файла

- `data/faq/faq_applicant.json` — для поступающих
- `data/faq/faq_student.json` — для студентов
- `data/faq/faq_teacher.json` — для преподавателей

Разделение по ролям нужно, чтобы в запрос попадала только нужная часть базы. Если раздел
полезен двум аудиториям — продублируй запись в оба файла, это нормально.

### Работа волнами — читай внимательно

Данных на сайте очень много, всю базу за хакатон не собрать, и это нормально. Поэтому работа
разбита на волны: **сначала вширь, потом вглубь**. После каждой волны база полноценно
работает — если время кончится на любой из них, ничего не сломается.

**Главное правило: коммить и пушить после каждой волны.** Не копи всё до конца — я подключаю
твои данные сразу, как они появляются.

| Волна | Что собираем | Сколько | К какому времени |
|---|---|---|---|
| **0. Каркас** | Самое частое по одной теме на роль: поступающему — сроки подачи документов, студенту — расписание и сессия, преподавателю — доступ к учебным системам | 3 записи на роль, **9 всего** | T+1:00 |
| **1. Вширь** | По одной записи на каждую категорию для каждой роли. Цель — чтобы у помощника был хоть какой-то ответ в любой теме | +15 | T+2:00 |
| **2. Вглубь по частому** | Подробности самых частых тем: стипендии по видам, общежитие по этапам заселения, пересдачи и их сроки, перечень документов по типам | +15 | T+3:00 |
| **3. Остальное** | Редкие, но реальные вопросы: перевод, восстановление, целевое обучение, воинский учёт, справки нестандартных видов | сколько успеешь | T+4:00 |

Волна 0 — критичная: без неё мне нечего отлаживать. Сделай её быстро и грубо, вылизывать
будешь в следующих волнах. Волна 3 — необязательная, её отсутствие на защите никто не заметит.

### Приоритет тем внутри волн

- **Поступающие:** сроки и правила приёма, перечень документов, проходные баллы, целевое
  обучение, стоимость платного обучения, общежитие для иногородних, дни открытых дверей.
- **Студенты:** расписание, сессия и пересдачи, стипендии, общежитие, справки, академический
  отпуск, перевод и восстановление, личный кабинет, студенческие организации.
- **Преподаватели:** доступ к учебным системам, оформление документов, расписание аудиторий,
  корпоративные сервисы.

### Формат записи

```json
{
  "id": "adm-001",
  "category": "admission",
  "title": "Сроки подачи документов на бакалавриат",
  "url": "https://misis.ru/applicants/admission/...",
  "keywords": ["подача документов", "сроки", "когда подавать", "приёмная кампания", "дедлайн подачи", "до какого числа", "бакалавриат"],
  "summary": "Два-три предложения по сути: что именно написано в разделе. Своими словами, без воды и без копирования абзацев целиком.",
  "full_text": "До 1500 символов основного содержания раздела — из него помощник соберёт ответ."
}
```

`category` — одно из: `admission` (поступление), `study` (учёба, расписание, сессия,
пересдачи), `campus_life` (общежитие, стипендии, студклубы, спорт, мероприятия),
`account` (личный кабинет, почта, Wi-Fi, доступы), `documents` (справки, выписки,
воинский учёт), `other`.

### Про `keywords` — 8–15 штук на запись

Обязательно включай **разговорные формулировки**, какими реально спрашивают, а не только
официальное название раздела:

- не только «академический отпуск», но и «взять академ», «уйти на год», «прервать учёбу»;
- не только «государственная академическая стипендия», но и «когда придут деньги»,
  «почему не пришла стипуха», «сколько платят за отличную учёбу».

Представь, как тот же вопрос задаёт растерянный абитуриент, а не сотрудник деканата.
Если времени в обрез — жертвуй длиной `full_text`, но **не количеством ключевых слов**:
без них раздел просто не найдётся.

## Часть 2: тестовые обращения — `data/faq/samples.json`

Пятнадцать обращений, как их пишут живые люди. Тоже волнами: **6 штук к T+2:00** (по две на
роль), остальные — когда закроешь волну 2 базы знаний. Формат:

```json
{
  "id": "s-01",
  "role": "applicant",
  "text": "Здравствуйте! Подскажите пожалуйста, когда подавать документы на бюджет и нужен ли оригинал аттестата сразу? И ещё общежитие иногородним дают всем?",
  "expected_categories": ["admission", "documents", "campus_life"],
  "expected_outcome": "answer",
  "note": "три вопроса в одном письме"
}
```

`role` — `applicant`, `student` или `teacher`.
`expected_outcome` — `answer`, если ответ есть в базе, или `ticket`, если нужна заявка.

**Обязательно включить по две-три штуки каждого вида:**

- письма с **несколькими вопросами сразу** — это ключевой пункт технического задания;
- письма, где **не хватает данных** («у меня не работает личный кабинет» — без имени, курса
  и описания ошибки);
- **расшифровки телефонного разговора** — с запинками, перебиваниями, повторами, разговорной
  речью;
- **эмоциональные** обращения — раздражение, срочность, «уже третий раз пишу»;
- вопросы **не по теме вуза** — помощник должен вежливо отказать;
- вопрос, ответа на который **заведомо нет в базе** — проверка пути обращения.

## Как собирать

Открывай разделы misis.ru, читай, пересказывай своими словами. **Не копируй тексты абзацами** —
нужна выжимка. Ссылка обязана вести на реально существующую страницу: помощник показывает её
пользователю, битая ссылка на защите — провал.

Файлы клади в `data/faq/`, ветка `feat/data-faq`. Коммить после каждой волны — я подключаю
данные сразу и проверяю поиск на реальных записях, а не на выдумке.

Расписание занятий собирать **не нужно** — оно берётся из отдельных файлов автоматически.

## Критерии приёмки

- JSON валиден (проверь любым онлайн-валидатором), кодировка UTF-8, русский текст читается.
- Все ссылки открываются.
- Нет двух записей с одинаковым `id` внутри одного файла.
- В каждой записи минимум 8 ключевых слов, среди них есть разговорные формулировки.
- В `samples.json` есть все шесть перечисленных видов обращений и все три роли.

## Чего НЕ делать

Не пиши код и не трогай папку `app/`. Не выдумывай факты: если на сайте информации нет,
лучше пропусти запись, чем напиши по памяти — помощник выдаст это пользователю как правду.
